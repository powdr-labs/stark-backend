# 2026-04-14-0830-increase-gkr-input-streams-roundrobin

Increase the GKR input evaluation thread count from 8 to 16 and switch from contiguous chunk distribution to round-robin (interleaved) work assignment. The GKR input eval for seg0 at APC 300 takes ~242ms with 8 threads using contiguous chunking on height-sorted work items, giving thread 0 all the largest AIRs (worst-case load balance). With pre-allocated per-thread buffers already eliminating mutex contention (since the prealloc-gkr-input-buffers task), higher thread counts are now viable without the allocation serialization that previously limited scaling. The combination of more threads (finer work granularity) and round-robin distribution (each thread gets a mix of large and small AIRs) should improve GPU stream overlap and reduce the critical-path thread time.
